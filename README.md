# ОренКод · Цифровая платформа ФСП Оренбургской области

Решение кейса «ОренКод 2026». Сейчас федерация ведёт спортсменов, соревнования, разряды и отчёты вручную в таблицах и переписке. Платформа собирает всё в одном месте: реестр по всем шести дисциплинам, полный цикл соревнования от положения до протокола, разряды и судейские категории с контролем сроков, рейтинг и сборную, официальные документы на бланке ФСП и уведомления на почту и в Telegram.

**Коротко:** все 8 обязательных блоков, 11 из 12 дополнительных сценариев (Д2–Д12) и 5 собственных сценариев. Пять кабинетов (федерация, спортсмен, тренер, судья, Минспорт) с переключением ролей без повторного входа. Все персональные данные в демо вымышлены.

**Стек:** FastAPI · SQLAlchemy 2 · PostgreSQL 17 · Alembic · React · TypeScript · Vite · Tailwind / shadcn/ui · Docker Compose · Telegram-бот на httpx (long polling) · Mailpit.

## Запуск

Нужны Docker Desktop (или Docker Engine) и Docker Compose v2. Команды выполняются из папки проекта.

```powershell
Copy-Item .env.example .env
# Укажите в .env случайный JWT_SECRET не короче 32 символов:
# python -c "import secrets; print(secrets.token_urlsafe(48))"
docker compose up --build -d
docker compose exec backend python -m app.seed --demo
```

| Что | Адрес |
| --- | --- |
| Интерфейс | http://localhost:8080 |
| Swagger API | http://localhost:8000/docs |
| Состояние API и БД | http://localhost:8000/api/health |
| Почтовый ящик Mailpit | http://localhost:8025 |
| Навигатор для новичка (без входа) | http://localhost:8080/start |

При старте backend сам применяет миграции и заполняет справочники. Демоданные загружаются отдельной командой `--demo`, повторный запуск не создаёт дубликатов и докладывает в уже загруженную базу данные новых функций (группы и занятия, заявки на разряд, интеграции, чат). Подробнее о данных: [docs/DATABASE_DATA.md](docs/DATABASE_DATA.md).

Пароль у всех: `DemoPass2026!`

| Аккаунт | Что внутри |
| --- | --- |
| `admin@demo.example` | Федерация. Есть все роли — удобно переключаться между кабинетами без выхода. Две заявки на разряд и категорию ждут решения, в «Интеграциях» — демо-токен и отключённый вебхук |
| `athlete@demo.example` | Спортсменка без тренера: сама подаёт заявки на разряд, есть предупреждение для апелляции, состоит в учебной группе с занятиями и заочным заданием |
| `coach@demo.example` | Тренер с пятью подопечными и учебной группой, есть спортсмен, готовый к переводу на следующий этап, и переписка с `athlete1@demo.example` |
| `judge@demo.example` | Судья с действующей категорией, работал главным судьёй на демо-соревнованиях, подал заявку на первую категорию |

Ещё 17 спортсменов: `athlete1@demo.example` … `athlete17@demo.example`. Пароль можно сменить до первой загрузки: `docker compose exec -e DEMO_PASSWORD=... backend python -m app.seed --demo`.

## Сквозной сценарий за 3 минуты

1. Войдите как `admin@demo.example`. В «Соревнованиях» создайте турнир: даты начала, окончания и срок заявок — сегодня, дисциплина «Алгоритмы», план «Оренбургская область», любой номер.
2. В карточке нажмите «Открыть приём заявок».
3. Вверху переключите кабинет на «Спортсмен» и подайте заявку из карточки.
4. Вернитесь в «Федерацию» и одобрите заявку. На вкладке «Судейская коллегия» можно назначить судью с должностью.
5. Закройте приём заявок. На вкладке «Результаты и протокол» укажите места и баллы всех одобренных участников (одинаковые места допускаются по правилу «1, 1, 3») и опубликуйте.
6. Скачайте протокол в PDF, DOCX или XLSX. В «Результатах» спортсмена появилось выступление, в «Рейтинге и сборной» — 40 баллов за 1 место регионального уровня.
7. Нажмите «Исправить протокол»: появится новая редакция с основанием, рейтинг пересчитается, история редакций сохранится.
8. В «Рейтинге и сборной» отметьте спортсменов, сохраните сборную и скачайте список и проект приказа.

Сервер не принимает заявки после дедлайна и не даёт опубликовать результаты до окончания соревнования, поэтому для проверки в другой день ставьте подходящие даты.

## Чего нет и ограничения

- **Д1 (OpenID Connect)** не реализован. Ограничения Д3 описаны в [сценарии групп и занятий](docs/TRAINING_GROUPS.md).
- **ЕВСК:** в кейсе нет таблиц ЕВСК, поэтому платформа только подсвечивает результаты по условиям, которые вносит федерация. Автоматического присвоения разрядов нет. Три условия в демо помечены как демонстрационные.
- **Нормативы ФССП:** пороги в демо — ориентир для показа, их нужно сверить с приказом Минспорта России № 445.
- **Формы документов:** образцов заказчика в кейсе нет, поэтому шаблоны построены по общим правилам делопроизводства (бланк, номер и дата, подписи с расшифровкой). Реквизиты по умолчанию вымышленные и задаются переменными `FSP_*`.
- **Численность по годам** учитывает переходы между организациями. Муниципалитет в разрезе — текущий, его история не ведётся.
- **Протокол:** исправление не меняет состав участников (снятия спортсмена с удалением из протокола нет). Присвоенные разряды при исправлении не отзываются автоматически — федерация видит предупреждение.
- **Аккаунты:** нет восстановления пароля, подтверждения email и промышленного rate limit. Электронной подписи документов нет.
- **Почта:** по умолчанию письма уходят в локальный Mailpit и не доставляются в интернет. Для реальной доставки задайте SMTP в `.env` — см. [docs/FEATURES.md](docs/FEATURES.md#почта).
- Перед работой с реальными персональными данными нужны HTTPS, резервное копирование и проверка мер защиты по 152-ФЗ.

## Архитектура

```text
frontend/        React + Vite + TypeScript + Tailwind, shadcn/ui, TanStack Query
backend/
  app/models/    54 таблицы SQLAlchemy 2.x
  app/routers/   REST API по модулям: соревнования, реестр, отчёты, апелляции, нормативы…
  app/services/  рейтинг, протоколы, документы PDF/DOCX/XLSX, уведомления, права доступа
  alembic/       миграции до 0023 (объединение веток Д3 и платформ)
  tests/         интеграционные тесты pytest
  app/seed.py    справочники и вымышленные демоданные
bot/             Telegram-бот, отдельный процесс
docs/            модель данных, API, описание сценариев, результаты проверок
```

- **Безопасность.** Пароли хешируются Argon2. JWT на 120 минут плюс HttpOnly-cookie для сохранения входа на 30 дней. Роли читаются из БД при каждом запросе; заголовок активной роли не может дать прав, которых у аккаунта нет. Бизнес-событие, уведомление, запись в журнал и изменение данных пишутся в одной транзакции.
- **Документы.** Все выгрузки собираются из одного описания `OfficialDocument` ([backend/app/services/documents.py](backend/app/services/documents.py)): бланк ФСП, A4, кириллица в PDF, повторяющаяся шапка таблиц. Формулы из пользовательского текста экранируются при экспорте в XLSX.
- **Уведомления.** Очередь хранится в БД, worker повторяет отправку каждые 60 секунд. Почта и Telegram доставляются независимо, у каждого канала свой статус.

## Telegram-бот

Бот проекта: [@orencode_bot](https://t.me/orencode_bot). Добавьте в корневой `.env` значения `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `PUBLIC_SITE_URL`:

```dotenv
TELEGRAM_BOT_TOKEN=<токен от @BotFather, передаётся отдельно и не хранится в репозитории>
TELEGRAM_BOT_USERNAME=orencode_bot
```

Затем выполните:

```powershell
docker compose --profile telegram up --build -d
```

Аккаунт привязывается одноразовым 8-значным кодом со страницы «Уведомления». Бот показывает соревнования, заявки, сроки и назначения, присылает уведомления и напоминания о старте. Данные меняются только на сайте. Создание бота через BotFather и диагностика описаны в [bot/README.md](bot/README.md).

## Разработка без Docker

Нужны Python 3.12+, Node.js 22+ и PostgreSQL 17+.

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Настройте DATABASE_URL и JWT_SECRET в backend/.env.
# В Windows для PDF задайте PDF_FONT=C:/Windows/Fonts/arial.ttf
alembic upgrade head
python -m app.seed --demo
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173 — Vite проксирует `/api` в FastAPI. Пользуйтесь одним адресом сайта: у `localhost` и `127.0.0.1` разные cookies.

## Проверки

```powershell
cd backend
pytest -q
alembic check
cd ../frontend
npm run build
npm audit
```

Тесты по умолчанию работают на изолированной SQLite в памяти с внешними ключами. Чтобы прогнать их на PostgreSQL, создайте пустую БД `orencode_test` и задайте `TEST_DATABASE_URL`:

```powershell
$env:TEST_DATABASE_URL="postgresql+psycopg://orencode:password@localhost:5432/orencode_test"
```
