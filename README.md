# ОренКод · Цифровая платформа ФСП Оренбургской области

Работающий MVP по кейсу «ОренКод 2026»: четыре кабинета, шесть дисциплин, полный цикл соревнования, рейтинг, сборная и документы. Все демонстрационные персональные данные вымышлены.

## Быстрый запуск с PostgreSQL

Требуются Docker Engine / Docker Desktop и Docker Compose v2. Команды выполняются из папки проекта.

```powershell
Copy-Item .env.example .env
# Укажите в .env случайный JWT_SECRET (не менее 32 символов).
# Например: python -c "import secrets; print(secrets.token_urlsafe(48))"
docker compose up --build -d
docker compose exec backend python -m app.seed --demo
```

- Интерфейс: http://localhost:8080
- Swagger API: http://localhost:8000/docs
- Состояние API и БД: http://localhost:8000/api/health
- Почтовый ящик Mailpit: http://localhost:8025

При старте backend выполняет `alembic upgrade head` и инициализацию справочников. Персональные демоданные загружаются только отдельной командой `--demo`, повторный запуск не создаёт дубликаты. Данные PostgreSQL хранятся в именованном Docker volume.

## Сквозная демонстрация за 3 минуты

1. Войдите как `admin@demo.example`. В разделе «Соревнования» создайте турнир. Для быстрой проверки укажите сегодняшние дату начала, окончания и срок подачи заявок, дисциплину «Алгоритмы», план «Оренбургская область» и произвольный демонстрационный номер.
2. Откройте карточку и нажмите «Открыть приём заявок».
3. Вверху переключите кабинет на «Спортсмен» без выхода из аккаунта. Вернитесь в карточку и подайте заявку. У этого демоаккаунта есть профиль спортсмена и дисциплина «Алгоритмы».
4. Переключитесь обратно на «Федерация», откройте карточку и одобрите заявку.
5. При необходимости во вкладке «Судейская коллегия» назначьте судью с должностью. Демо-категории действуют ещё 320 дней.
6. Закройте приём заявок. Во вкладке «Результаты и протокол» укажите места **всех одобренных** участников и баллы. Одинаковые места допускаются по правилу «1, 1, 3»; для командного зачёта создайте и допустите команды во вкладке «Команды», затем введите один результат на команду. Опубликуйте.
7. Скачайте протокол PDF/DOCX/XLSX. Проверьте «Результаты» и «Рейтинг и сборная»: за первое региональное место начисляется 40 рейтинговых баллов.
   Чтобы исправить протокол, нажмите «Исправить протокол», измените строки и укажите основание. Появится новая редакция, рейтинг пересчитается. В «Истории редакций» видны изменения и предупреждения о затронутых разрядах, каждую редакцию можно скачать.
8. Выберите спортсменов в рейтинг-таблице, сохраните сборную и скачайте список / проект приказа.

Для полного цикла в другой день создавайте соревнование с соответствующими датами: сервер запрещает заявки после дедлайна и публикацию результатов до завершения соревнования.

## Рейтинг из PDF

| Уровень | 1 место | 2 место | 3 место |
| --- | ---: | ---: | ---: |
| Чемпионат России | 100 | 80 | 60 |
| Первенство России | 80 | 60 | 40 |
| Межрегиональные | 60 | 45 | 30 |
| Региональные | 40 | 30 | 20 |

Места ниже третьего дают 0: дополнительных значений PDF не задаёт. Сумма за дисциплину и сезон умножается на **1,2**, если призовых результатов не менее двух. Отстранение включительно по текущую дату исключает спортсмена. Баллы выступления и рейтинговые баллы — разные величины. Рейтинг основан на опубликованных протоколах; пересчитывается при публикации и чтении таблицы, поэтому изменение правил и истечение отстранения учитываются сразу. PostgreSQL advisory lock сериализует пересчёт сезона.

## Почта

По умолчанию письма реально передаются SMTP-серверу Mailpit в Docker и видны в его интерфейсе. Это локальный приёмник: он **не доставляет письма в интернет**. Для рабочего внешнего почтового канала добавьте в корневой `.env`:

```dotenv
SMTP_HOST=smtp.example.org
SMTP_PORT=587
SMTP_USER=your-user
SMTP_PASSWORD=your-password
SMTP_TLS=true
MAIL_FROM=federation@example.org
```

Затем `docker compose up -d backend`. Для реальной доставки используйте реальные адреса зарегистрированных получателей; адреса `@demo.example` намеренно вымышленные. В UI видны очередь, отправка или ошибка с повтором. Внешняя SMTP-доставка требует предоставленного почтового сервера; доступ к реальному почтовому аккаунту при разработке не использовался. Работает один backend-worker; отдельный брокер не нужен.

## Разработка без контейнеров

Требуются Python 3.12+, Node.js 22+ и запущенный PostgreSQL 17+. Из корня проекта:

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# Настройте DATABASE_URL и JWT_SECRET в backend/.env.
# В Windows для PDF задайте PDF_FONT=C:/Windows/Fonts/arial.ttf
alembic upgrade head
python -m app.seed --demo
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

В другом терминале из корня:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api` в FastAPI. При необходимости установите SMTP-приёмник отдельно или используйте SMTP-настройки. Без SMTP уведомления сохраняются в кабинете и остаются в очереди.

```text
frontend/                  React + Vite + TypeScript + Tailwind
  src/components/ui/       компоненты shadcn/ui на Radix и CVA
  src/                     маршруты, формы, API, TanStack Query
backend/
  app/models/              26 связанных таблиц SQLAlchemy 2.x
  app/schemas/             Pydantic: входные данные и инварианты
  app/routers/             Auth, Registry, Competitions, Federation, Reports
  app/services/            права на спортсменов, рейтинг, документы, SMTP
  alembic/versions/        замороженная начальная миграция
  tests/                   интеграционные проверки
  app/seed.py              справочники и фиктивные демоданные
docs/                      требования, модель/API, результаты проверок
```

JWT действует 120 минут, хранится в sessionStorage и отправляется в `Authorization: Bearer`. Пароли хешируются Argon2. Набор ролей читается из БД при каждом запросе; заголовок активной роли не может дать отсутствующие права. Федерация выдаёт дополнительные роли в «Управлении». Запись бизнес-события, уведомления и изменение сущности выполняются в одной транзакции. Сервер блокирует строку соревнования на время изменений. PDF поддерживает кириллицу и повторяющиеся заголовки таблиц. Формулы из пользовательского текста экранируются при XLSX-экспорте.

## Границы MVP

- PDF содержит перечень документов, но не сами заданные формы. Шаблоны построены по общим правилам оформления (бланк с реквизитами, номер и дата, подписи с расшифровкой); для точного соответствия нужны образцы заказчика. Реквизиты по умолчанию вымышленные.
- В PDF нет таблиц ЕВСК. Внесение условий подсветки доступно, но полный нормативный движок ЕВСК и официальная оценка всех условий **не реализованы**. Нормативы не выдуманы.
- Историческая численность строится по годам начала/окончания занятий. Организация берётся из истории переходов: при смене организации в профиле указывается дата перехода, в год перехода спортсмен учитывается в новой организации. Для данных, внесённых до появления истории, считается, что спортсмен состоял в текущей организации с года начала занятий. Муниципалитет в разрезе — текущий, его история не ведётся.
- Командный зачёт использует общую заявку и подтверждённый состав; прежние протоколы с названиями команд сохранены для совместимости. Исправление протокола не меняет состав участников: снятие спортсмена и апелляции (Д5) не реализованы. Присвоенные разряды при исправлении не отзываются автоматически, федерация получает предупреждение в истории редакций.
- Положение загружается файлом; сертификат РУСАДА хранится как HTTP(S)-ссылка. Публичный паспорт выведен из использования; ранее загруженные документы согласий остаются в БД и публично недоступны. Регистрационное согласие хранится как версия текста, время и данные представителя. Электронная подпись документов не реализована.
- Есть создание аккаунтов через регистрацию, назначение ролей, редактирование спортсменов и организаций. Отдельный полный CRUD карточек тренеров/судей и их архивирование пока отсутствуют.
- Реализованы цифровой паспорт и справка об участии с QR (Д10). Остальные опциональные сценарии, интеграции с Госуслугами, восстановление пароля, подтверждение email и промышленный rate limit. Перед работой с реальными персональными данными нужны проверка согласий, прав доступа, эксплуатационная защита, резервное копирование и HTTPS.

Это проверяемый хакатонный MVP; указанные ограничения не выдаются за готовый функционал.

## Сводка выступлений подопечного

В кабинете тренера откройте «Мои спортсмены» и нажмите «Сводка выступлений» у подтверждённой активной связи. Отдельный экран показывает результаты опубликованных соревнований, фильтры по году и дисциплине, число выступлений, побед, призовых мест и лучшее место. Нажатие на название соревнования открывает его карточку. Сводка включает всю опубликованную историю спортсмена; доступ прекращается при приостановке или завершении связи. Неопубликованные результаты не учитываются.

API: `GET /api/coaching/athletes/{athlete_id}/summary?year=2026&discipline_id=1` (оба фильтра необязательны). Доступ разрешён тренеру с активной связью и федерации.

## Командные соревнования

При создании соревнования федерация выбирает командный зачёт, размер состава и начисление личного рейтинга за командный результат (по умолчанию выключено). Во вкладке «Команды» спортсмен создаёт команду и становится капитаном; тренер собирает состав из своих подопечных. Приглашение отправляется по публичному ID спортсмена из его профиля (`FSP-000123`); тренер выбирает из своих подопечных. Перед отправкой видны ФИО, ID, организация и муниципалитет. Каждый приглашённый самостоятельно подтверждает участие. Капитан или тренер подаёт общую заявку, федерация допускает команду либо возвращает на исправление с комментарием. Изменение допущенного состава снимает допуск и требует повторной подачи.

После закрытия заявок федерация вводит место и баллы один раз на допущенную команду. Результат появляется у каждого участника, в протоколе и в сводке тренера. Миграция `0007` сохраняет существующие соревнования и протоколы. Подробности, ограничения и проверка: [docs/COMPETITION_TEAMS.md](docs/COMPETITION_TEAMS.md).

## Профили спортсменов и справки

Нажатие на имя спортсмена открывает профиль с результатами после входа. В «Моём профиле → Результаты» спортсмен выбирает, какие разделы видят другие пользователи. Справки об участии находятся только в личном разделе «Результаты» и доступны спортсмену, федерации и его действующему тренеру по дисциплине. QR новых PDF ведёт на публичную проверку номера, соревнования и статуса без персональных данных; PDF остаётся закрытым. Старые публичные паспорта и ссылки на документы закрыты миграцией `0009`. Подробности: [профили и справки](docs/DIGITAL_PASSPORT_IMPLEMENTATION.md).


### Сохранение входа

Вход сохраняется на 30 дней через HttpOnly-cookie, короткий токен обновляется автоматически. «Выйти» отзывает сессию браузера. После обновления с версии без cookie нужно войти один раз. Пользуйтесь одним адресом сайта (например, `http://localhost:8080`): localhost и 127.0.0.1 имеют разные cookies. Требуется миграция `0010`; Docker запускает миграции при старте backend. Для применения выполните `docker compose up --build --force-recreate -d backend frontend`. Для HTTPS задайте HTTPS origin в PUBLIC_BASE_URL, чтобы cookie получала Secure.

## Назначения и отчёт судьи

В кабинете судьи два раздела. «Назначения» показывает соревнования, которые ещё не закончились (дата окончания сегодня или позже). «Мои соревнования» — прошедшие соревнования, где судья работал в коллегии, с отчётом: число соревнований, сколько раз главным судьёй, число участников по протоколам и дисциплины. Отчёт фильтруется по году и выгружается в PDF, DOCX и XLSX. Счётчик «Назначения» на обзоре считает только предстоящие.

API: `GET /api/assignments?scope=upcoming|past` (без `scope` — все назначения), `GET /api/judging/report?year=2026` и `GET /api/exports/judging.{pdf|docx|xlsx}?year=2026` (год необязателен). Отчёт доступен только судье.

## Шаблоны документов

Все выгрузки (протокол, проект приказа о сборной, список кандидатов, справка о выступлениях спортсмена, отчёты о численности и о судейской деятельности, демо-положение) собираются из одного описания `OfficialDocument` в `backend/app/services/documents.py` и выглядят как одна форма:

- бланк: полное наименование регионального отделения ФСП и строка реквизитов (адрес, ИНН, ОГРН, почта), двойная черта;
- вид документа заглавными (ИТОГОВЫЙ ПРОТОКОЛ, ПРИКАЗ, ОТЧЁТ, СПРАВКА), строка «дата — место составления — номер», заголовок;
- реквизиты содержания (дисциплина, сроки, редакция протокола, период отчёта и т. п.), таблица с повторяющейся шапкой и столбцом «№ п/п»;
- подписи: должность, линия «(подпись)», расшифровка. Протокол подписывают главный судья и главный секретарь из судейской коллегии, отчёт судьи — сам судья, отчёт о численности — председатель и исполнитель;
- приказ выгружается как проект: «ПРОЕКТ», пустые дата и номер для заполнения, преамбула со ссылкой на 329-ФЗ, «ПРИКАЗЫВАЮ:», подпись председателя, состав сборной — в приложении на отдельной странице; положение — с грифом «УТВЕРЖДАЮ».

PDF и DOCX — формат A4 по полям делопроизводства (левое 25 мм), в колонтитуле организация, дата формирования и номер страницы. XLSX оставлен табличным (заголовок, реквизиты, шапка в 3-й строке для фильтра), реквизиты бланка — в колонтитуле печати, подписи — под таблицей.

Реквизиты задаются переменными окружения backend: `FSP_NAME`, `FSP_SHORT_NAME`, `FSP_REQUISITES`, `FSP_CITY`, `FSP_HEAD_POSITION`, `FSP_HEAD_NAME` (без ФИО председателя на месте расшифровки остаётся линия).

## Навигатор для новичка (Д11)

Публичная страница http://localhost:8080/start открывается без входа. На странице входа на неё ведёт ссылка «Новичкам». На ней четыре шага «с чего начать», шесть дисциплин с кратким описанием, места для занятий с фильтром по дисциплине и муниципалитету и ближайшие соревнования с отметкой, открыт ли приём заявок. Кнопка «Регистрация» сразу открывает форму регистрации.

На странице нет персональных данных: только организации, муниципалитеты и число занимающихся. Черновики соревнований и организации, где остались только архивные тренеры, не показываются.

API: `GET /api/public/navigator`, без авторизации.
