# Telegram-бот ФСП

Самостоятельный процесс бота: команды, меню, расписание и очередь доставки находятся в этой папке. Общие модели, API привязки и миграции находятся в `backend`, интерфейс подключения — в `frontend`.

## Настройка

1. В Telegram откройте официальный `@BotFather`, выполните `/newbot`, задайте имя и username бота.
2. Добавьте в корневой `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=токен-из-BotFather
TELEGRAM_BOT_USERNAME=username_бота_без_@
PUBLIC_SITE_URL=http://localhost:8080
```

Токен не публикуйте и не добавляйте в Git. Для переходов из Telegram на телефоне задайте доступный ему адрес сайта, например HTTPS-адрес вашего стенда. `localhost` на телефоне указывает на телефон. Локальная привязка через Telegram и доставка сообщений работают без публичного входящего URL: бот сам обращается к Telegram через long polling.

3. Из корня проекта запустите:

```powershell
docker compose --profile telegram up --build -d
```

Backend сначала применяет миграции, затем запускается бот. Без профиля `telegram` отдельный процесс бота не запускается. Сайт работает и без Telegram-настроек.

4. Войдите на сайт, откройте «Уведомления» и нажмите «Привязать Telegram». Сайт покажет одноразовый 8-значный код и оставшееся время. Скопируйте код, откройте бота и отправьте ему эти цифры сообщением. Проверьте имя аккаунта и нажмите «Подтвердить подключение». Код действует 10 минут; новый код отменяет предыдущий. После пяти попыток ввода в одном чате действует ограничение до конца 10-минутного окна.

## Меню и команды

- `/start`: меню с соревнованиями, заявками, сроками и назначениями.
- «Личный кабинет»: собственный профиль из тех же данных, что на сайте, без РУСАДА. Для спортсмена — организация, дисциплины и годы занятий, этап, разряды, тренеры и согласия; для тренера/судьи — контакты, организация, дисциплины и квалификация.
- «Выход из аккаунта»: отключение и отмена ожидающей доставки. Для повторного подключения нужен новый код с сайта.
- «Выбор роли»: последняя кнопка меню, выбор одной из актуальных ролей аккаунта; кабинет сайта не меняется.

В списке Telegram-команд остаётся только `/start`. Переходы между разделами, выбор роли и пагинация отправляют новый экран и удаляют прежнее сообщение с кнопками. Если отправка не удалась, старое сообщение сохраняется. Кнопки страниц соревнований являются URL-ссылками, а не callback-пунктами выбора; нажатие URL-кнопки не создаёт событие для бота и не удаляет сообщение.

Личные данные доступны только в личном чате. Списки выводятся по 5 записей. Бот показывает данные платформы, а действия выполняются на сайте. Пароль сайта в Telegram не запрашивается. Старые уведомления после подключения не рассылаются. Код хранится только в виде HMAC-хеша; не передавайте его другим людям.

## Напоминания

Допущенные спортсмены, их активные тренеры по дисциплине и назначенные судьи получают напоминания за 3 календарных дня в 09:00, в день старта в 09:00 и за час до старта. Время считается в часовом поясе соревнования, по умолчанию `Asia/Yekaterinburg`.

Точное время начала необязательно. Без него нет напоминания за час. Если старт раньше или в 09:00, утреннее сообщение в день старта пропускается. После старта или публикации результатов напоминания о предстоящем старте прекращаются.

Дедлайн регистрации: за 3 и 1 день, для подходящих по возрасту и дисциплине спортсменов без заявки и их тренеров. Разряды, категории, отчётные сроки и ходатайства до 1 февраля: за 30, 7 и 1 день, в 09:00 по времени Оренбурга.

Федерация может изменить дату и время через «Изменить расписание» в карточке открытого/закрытого соревнования. Система проверяет возраст допущенных спортсменов и сроки категорий назначенных судей. Участникам и судьям отправляется сообщение о переносе; старые напоминания отменяются.

Очередь проверяется раз в минуту. После простоя отправляется последнее актуальное напоминание для каждого события, без пачки пропущенных этапов. Прочие события доставляются после сохранения, при ближайшем проходе очереди. Почта и Telegram имеют независимый учёт доставки.

## Диагностика

```powershell
docker compose --profile telegram ps
docker compose logs --tail=100 bot
```

На сайте у уведомления виден статус Telegram-доставки. При блокировке бота сначала разблокируйте его в Telegram, затем отключите привязку на сайте и подключите заново.

Если `PUBLIC_SITE_URL` указывает на `localhost`, адрес URL-кнопки использует `127.0.0.1` с тем же портом. Это локальный адрес: открыть его можно на компьютере с проектом. Для телефона нужен доступный адрес стенда в `PUBLIC_SITE_URL`. Если Telegram отклоняет URL-кнопку, адрес приходит обычным текстом; меню продолжает работать. Ошибка отправки одного ответа не останавливает следующие нажатия: постоянные ошибки подтверждаются в курсоре, временные повторяются.

Запускайте только один экземпляр бота для одного токена. Процесс использует PostgreSQL advisory lock от второго запуска с той же базой. Токен должен быть выделен этому проекту: другой poller с другой базой не блокируется этой защитой. Если токен ранее использовался с webhook, удалите webhook через Telegram Bot API перед запуском long polling.

Временные ошибки повторяются с увеличением задержки до 30 минут; для лимитов Telegram учитывается `retry_after`. При неопределённом результате сетевого запроса возможен повтор сообщения. Отправка в Telegram не меняет отметку «прочитано» на сайте.

## Запуск без Docker

Нужны зависимости backend, PostgreSQL с применёнными миграциями и отдельный терминал. Из корня проекта в PowerShell:

```powershell
$env:PYTHONPATH = "$PWD;$PWD\backend"
# Корневой .env должен содержать JWT_SECRET и DATABASE_URL локального PostgreSQL.
backend\.venv\Scripts\python.exe -m bot
```

Не используйте SQLite для рабочего процесса бота: защита от параллельного polling рассчитана на PostgreSQL.

## Проверка

Из папки `backend`, после установки зависимостей:

```powershell
.venv\Scripts\python.exe -m pytest -q
```

Новые проверки: `backend/tests/test_telegram.py`. Telegram API заменён тестовым адаптером; тесты не отправляют сообщения реальным пользователям. Для ручной проверки подключите тестовый аккаунт с фиктивными данными, одобрите заявку, назначьте судью и опубликуйте протокол. Соответствующие сообщения должны появиться в Telegram. Проверку часовых интервалов выполняют автоматические тесты с управляемым временем.

API привязки: `GET /api/telegram/link`, `POST /api/telegram/link-code`, `DELETE /api/telegram/link`. Выпуск кода возвращает `code`, `bot_url`, `expires_at`. Старый путь `POST /api/telegram/link-token` оставлен как deprecated alias с тем же новым ответом. Перенос расписания: `PATCH /api/competitions/{id}/schedule`. Все запросы требуют авторизации и проверяют права.
