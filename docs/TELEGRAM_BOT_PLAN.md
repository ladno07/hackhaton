# Telegram-бот ФСП: план реализации

Статус: код первой версии реализован. Автоматические проверки выполняются без реального токена; проверка доставки в настоящий Telegram требует настройки BotFather.
Проект: `G:\projs\hackhaton`.

## Цель и границы первой версии

Бот служит внешним каналом уведомлений и позволяет просматривать данные платформы. Он поддерживает кабинеты спортсмена, тренера, судьи и федерации. Подача заявок, решения федерации и внесение результатов выполняются на сайте.

Бот получает данные из платформы. Регистрацию и прохождение заданий на сторонних соревновательных площадках он не отслеживает.

В первую версию не входят интеграции с внешними площадками, рейтинг, навигатор новичка и подача заявок внутри Telegram.

## Пользовательские возможности

| Раздел | Поведение |
| --- | --- |
| Привязка | На странице уведомлений пользователь нажимает «Привязать Telegram», получает одноразовый 8-значный код, отправляет его боту и подтверждает аккаунт. Пароль в Telegram не вводится. |
| Заявки | Сообщения об одобрении и отклонении заявки на соревнование, разряд или категорию с комментарием федерации. |
| Соревнования | Открытие регистрации, обновление положения, публикация и исправление протокола. Карточка содержит дисциплину, даты, время, место, формат и ссылку на сайт. |
| Контроль сроков | После допуска — начало и окончание соревнований; также разряды, категории, отчётность и ходатайства на премии. Напоминания о сроке подачи заявки отключены. |
| Назначения судьи | Сообщение о назначении с соревнованием и должностью; список собственных назначений. |
| Личный кабинет | Собственный профиль из данных сайта без РУСАДА, с учётом выбранной роли. |
| Выход из аккаунта | Отключение Telegram и отмена ожидающих сообщений. Возобновление требует нового кода. |

Меню: «Личный кабинет», «Соревнования», «Мои заявки», «Мои сроки», «Мои назначения», «Выбор роли», «Выход из аккаунта» (последняя кнопка). Списки выводятся по 5 записей. Переходы меню удаляют предыдущий экран после успешной отправки нового; страницы соревнований открываются URL-кнопками. Нажатие URL-ссылки не поступает боту, поэтому сообщение при нём не удаляется. Недоступные роли разделы скрываются, а доступ дополнительно проверяется сервером.

В боте есть отдельный выбор активной роли. Он не меняет кабинет сайта. Тренер видит только своих активных подопечных с учётом дисциплины; судья видит свои назначения. Федерация видит доступные ей заявки и сроки.

Набор разделов: спортсмен — профиль, соревнования, свои заявки и сроки; тренер — профиль, подопечные, их заявки, соревнования и разряды; судья — профиль, назначения, соревнования и своя категория; федерация — профиль, заявки участников, квалификации и отчётные сроки. Выбор роли и выход завершают каждое меню.

«Мои назначения» присутствуют только у судьи; у федерации назначения доступны в карточках соревнований на сайте. В списках сохраняются кнопки «Назад» и «Далее», без отображения номера страницы.

Автоматические сообщения охватывают все актуальные роли пользователя, содержат подпись роли и не дублируются для одного получателя по одному событию.

## Расписание

Все календарные напоминания рассчитываются по часовому поясу соревнования. Для разрядов, категорий и сроков федерации используется `Asia/Yekaterinburg`.

| Событие | Когда | Получатели |
| --- | --- | --- |
| Начало соревнования | За 3 календарных дня в 09:00; в день старта в 09:00; за час до точного старта | Допущенные спортсмены, их активные тренеры по дисциплине, назначенные судьи |
| Открытие приёма заявок | После открытия регистрации | Только спортсмены, подходящие по действующей дисциплине, возрасту и полу из профиля |
| Окончание соревнования | За 1 день и в день окончания в 09:00, только во время соревнования | Только спортсмены с одобренной заявкой |
| Истечение разряда | За 30, 7 и 1 день в 09:00 | Спортсмен и его активные тренеры по дисциплине разряда |
| Истечение судейской категории | За 30, 7 и 1 день в 09:00 | Только соответствующий судья |
| Отчётный срок | За 30, 7 и 1 день в 09:00 | Федерация |
| Ходатайства на премии до 1 февраля | За 30, 7 и 1 день в 09:00 | Федерация |
| Решение по заявке, назначение, открытие регистрации, положение, протокол | После сохранения события, при ближайшей проверке очереди | Получатели события в пределах прав |

Дополнительные правила:

- У соревнования появляются необязательное время начала и часовой пояс с default `Asia/Yekaterinburg`.
- Старые записи сохраняют даты. Без времени старта нет напоминания за час; календарные напоминания остаются.
- Если точный старт раньше или в 09:00, утреннее сообщение в день старта пропускается.
- После фактического старта напоминания о предстоящем начале не отправляются. Без времени начала календарное сообщение «сегодня» допустимо в день старта, но не позже него.
- Для опубликованных результатов напоминания о предстоящем старте прекращаются.
- Перед отправкой повторно проверяются допуск, активная тренерская связь, назначение, роли и доступность сущности.
- Изменение даты, времени или часового пояса сообщает об изменениях заинтересованным участникам и судьям, отменяет старое расписание и создаёт новое. Нужен отдельный разрешённый федерации путь изменения расписания опубликованного для участников соревнования: текущий общий редактор допускает только черновики.
- После простоя отправляется только последнее актуальное напоминание в каждой цепочке, без накопленной пачки. Просроченные напоминания подавляются.
- Этапы напоминаний, наступившие до регистрации аккаунта, не создаются для него. В Telegram также подавляются этапы до момента подключения, даже если запись уведомления впервые создалась уже после подключения.
- Напоминания спортсмену о соревновании доступны только после одобрения заявки; этапы до времени одобрения не догоняются. Отзыв допуска, окончание соревнования и публикация результатов прекращают напоминания об окончании.
- Повторная проверка расписания не создаёт новое событие с тем же ключом. Ключ расписания учитывает сущность, получателя, тип напоминания и версию даты/времени.

## API, хранение и безопасность

### Привязка

- `GET /api/telegram/link`: состояние собственной привязки и доступность подключения.
- `POST /api/telegram/link-code`: одноразовый код из 8 цифр, `bot_url` и `expires_at`, срок действия 10 минут. Старый `/link-token` остаётся deprecated alias с новым форматом ответа.
- `DELETE /api/telegram/link`: отключение собственной привязки и отмена ожидающей доставки для неё.
- Все три метода требуют авторизации сайта; пользователь определяется из сессии, а не из переданного `user_id`.
- Код генерируется криптографически случайно, хранится только в виде HMAC-хеша; выпуск нового отменяет предыдущий. Подтверждение в личном чате атомарно расходует код. Ограничение ввода: 5 попыток на чат за 10 минут, с сохранением счётчика в БД.
- Один Telegram-аккаунт связан с одним аккаунтом платформы и наоборот. Заменять существующую привязку молча нельзя: сначала отключение.
- Команды и подтверждение работают только в личном чате. Telegram ID хранится целым 64-битным числом.
- Роли и владение данными проверяются при каждом запросе и callback. Идентификаторы в кнопках не считаются доказательством доступа.
- Единственная команда — `/start`. Привязка отключается кнопкой «Выход из аккаунта». Секреты и коды привязки не попадают в логи.

### Очередь

- Существующие `notifications` остаются источником событий и уведомлений кабинета.
- Telegram получает отдельные записи доставки: уведомление, привязка, состояние, попытки, следующая попытка, время отправки и последняя ошибка.
- Хранятся отдельные сущности привязки, одноразовых кодов, счётчиков попыток и позиции обработанных Telegram updates.
- Почтовая и Telegram-доставка независимы: ошибка одного канала не блокирует другой.
- При подключении не пересылать накопленную историю. Для повторного подключения также действует новая граница начала доставки.
- Повторять сетевые ошибки с увеличением интервала до 30 минут; соблюдать `retry_after` Telegram. Ошибка одного получателя не задерживает остальных.
- При блокировке бота прекратить доставку пользователю и показать состояние на сайте.
- При неопределённом результате HTTP-запроса возможен дубль сообщения. Абсолютная гарантия exactly-once не заявляется.

## Процессы, интерфейс и конфигурация

- Один отдельный процесс бота в Docker Compose: long polling для команд и проверка очереди/расписания раз в минуту. Хранить обработанный `update_id` в БД; исключить параллельный запуск двух poller для одного токена.
- Использовать общие сервисы чтения и проверки прав с сайтом; не обращаться к HTTP-обработчикам без явного контекста пользователя и роли.
- Добавить миграцию Alembic для времени/часового пояса соревнования, привязок, токенов, доставок и позиции polling.
- В форме соревнования и карточке показывать время и часовой пояс. Валидировать IANA timezone на сервере; предусмотреть `tzdata` для Windows.
- На странице «Уведомления» показать подключение, код с таймером и копированием, отключение и состояние доставки каждого канала отдельно.
- Переменные: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `PUBLIC_SITE_URL`. Токен доступен только серверным процессам, не фронтенду.
- Без настроенного токена сайт продолжает работать, подключение Telegram недоступно с понятным объяснением.
- Ссылки строятся из `PUBLIC_SITE_URL`. Для телефона нужен доступный телефону адрес; `localhost` относится к самому устройству.
- Миграции выполняются до запуска бота. Отдельный брокер сообщений для первой версии не требуется.

## Проверки и критерии готовности

- Одноразовый, истёкший и повторно выпущенный код; чужая и занятая привязка; повторное подтверждение; кнопка выхода; переподключение без старой истории.
- Все четыре роли, независимость выбора роли от сайта, отзыв роли, архивные карточки и запрет доступа к чужим данным через подменённые callback.
- Пагинация по 5 записей и корректные пустые состояния каждого раздела.
- Расписание с управляемыми часами: границы 09:00, ранний старт, отсутствие времени, часовой пояс, перенос даты, поздний допуск, снятие назначения, завершённая тренерская связь и перезапуск процесса.
- Отбор по возрастным группам, дисциплине и наличию заявки для напоминаний о дедлайне.
- Независимость каналов, сетевые ошибки, `retry_after`, блокировка бота, рестарт polling и защита от повторной постановки в очередь.
- Миграция на существующей БД с сохранением старых соревнований; запуск сайта без Telegram-настроек.
- Сборка frontend и релевантные backend-тесты проходят.
- Сквозное демо: привязка → одобрение заявки → напоминание → назначение судьи → публикация результата → сообщение со ссылкой.
- README содержит настройку через BotFather, переменные окружения, запуск, диагностику и перечень реализованных сценариев. Нереализованные пункты не отмечаются готовыми.
