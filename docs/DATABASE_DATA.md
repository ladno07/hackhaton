# Данные приложения и повторная загрузка

## Откуда берутся данные

Интерфейс получает записи через API backend. Основное хранилище — PostgreSQL: база
`orencode`, служба `db` в `docker-compose.yml`. Данные сохраняются в Docker volume
`postgres_data` (в текущем проекте — `hackhaton_postgres_data`). Пересборка приложения
или перезапуск контейнеров не очищают эту базу.

В `backend/app/seed.py` описаны справочники, вымышленные демонстрационные пользователи,
спортсмены, тренеры, соревнования и результаты. Спортсмены на снимках экрана —
18 участников из списка `names` и Алексей Северный с ролью спортсмена.
Первичная загрузка демонстрационного набора:

```powershell
docker compose exec -T backend python -m app.seed --demo
```

Команда заполняет первоначальную демонстрационную базу. Если демонстрационный
администратор уже существует, повторная команда **не сбрасывает** текущие записи,
изменения и переписку. Обычный запуск backend без `--demo` инициализирует справочники
и применяет миграции, но не создаёт демонстрационных пользователей.

Новые регистрации, изменения профилей, связи и сообщения записываются в ту же БД
через интерфейс. Сообщения хранятся в `coach_chat_messages`; это пользовательская
переписка, она не создаётся через `seed.py`.

## Состояние после очистки 28 октября 2026 года

Сохранены все 19 демонстрационных спортсменов со снимков экрана. Удалены лишняя учётная
запись и карточка спортсмена, его связь с тренером,
дисциплины и связанные служебные записи. Удалены все 7 сообщений чатов, уведомления
о них и связанные записи очереди Telegram. Данные остальных пользователей,
соревнований, результатов и действующие связи сохранены.

Локальные снимки PostgreSQL:

- `backups/orencode-before-cleanup-20261028.dump` — состояние до очистки.
- `backups/orencode-clean-20261028.dump` — очищенная база: 19 спортсменов, пустые чаты.

Каталог `backups/` исключён из Git. Снимки содержат учётные записи и данные приложения;
их нужно хранить локально и переносить отдельно, если проект запускается на другой машине.

## Как заново загрузить именно очищенные данные

Выполнить из корня проекта в PowerShell. Восстановление заменяет текущие данные
снимком от 28 октября: изменения, сделанные позднее, в него не входят.

```powershell
docker compose stop backend bot
docker compose cp ./backups/orencode-clean-20261028.dump db:/tmp/orencode-clean-20261028.dump
docker compose exec -T db pg_restore -U orencode -d orencode --clean --if-exists --single-transaction --no-owner --no-privileges /tmp/orencode-clean-20261028.dump
docker compose start backend bot
```

Выполнять следующую команду после успешного завершения предыдущей. Затем обновить
страницу и войти заново, если текущая сессия была создана после снимка.
Если бот не используется, убрать `bot` из команд остановки и запуска.

## Обновить приложение, сохранив текущую базу

```powershell
docker compose up -d --build
```

Затем обновить страницу (`Ctrl+F5`). Для обычного перечитывания данных с сервера
достаточно обновить страницу; восстановление снимка и повторная загрузка `--demo`
для этого не нужны.

Не использовать `docker compose down -v` для обновления приложения: эта команда
удаляет volume с базой.
