# Модель данных и API

## Связи

`users → user_roles → roles`: один аккаунт имеет несколько ролей. `athletes`, `coaches`, `judges` связаны с аккаунтом 1:1. Профиль не удаляется при снятии роли, поэтому сохраняется история.

`organizations → athletes/coaches/judges`. Карточки тренера и судьи (`coaches`, `judges`) хранят муниципалитет, контакты, квалификацию, стаж и «о себе»; дисциплины — в `coach_disciplines` и `judge_disciplines`. Карточка не удаляется, а переносится в архив (`archived_at`, `archive_reason`): архивный тренер не создаёт связи, его активные связи приостанавливаются, неподтверждённые завершаются; архивного судью нельзя назначить, он не подаёт заявки на категорию. История и протоколы сохраняются, карточку можно восстановить. `athlete_disciplines` задаёт дисциплины и годы занятий. `athlete_organizations` хранит периоды членства спортсмена в организациях (`start_date`, `end_date` включительно, открытый период — текущий); `athletes.organization_id` дублирует текущую организацию. Смена организации в профиле закрывает открытый период днём раньше даты перехода (`organization_since`, по умолчанию сегодня) и открывает новый; дата не может быть в будущем или внутри закрытой истории. Отчёт о численности относит спортсмена к организации последнего периода, пересекающего год. `athlete_coaches` связывает спортсмена, тренера и дисциплину; `link_history` хранит переходы статуса с автором и временем.

`competitions → disciplines / competition_types`; в соревновании хранятся даты, возраст, формат, статус (`regional` / `interregional` / `national`), календарный план и номер, ссылка на положение. Тип берётся из справочника `competition_types`, у каждого типа есть класс для рейтинга (`main` — чемпионат, кубок; `junior` — первенство; `other`). Уровень для рейтинга `rating_level` не вводится вручную: он вычисляется из пары «статус + класс типа» при создании и правке черновика. Региональное и межрегиональное идут своим уровнем; у всероссийского `main` даёт чемпионат России, `junior` первенство России, `other` межрегиональный уровень. По `rating_level` начисляются баллы и подбираются подсказки ЕВСК. Файл положения хранится отдельно в `competition_regulations` (bytea, одна запись на соревнование, проверка расширения и сигнатуры, до 10 МБ); `PUT/DELETE/GET /api/competitions/{id}/regulation`. Справочник `age_groups` (название, пол, возраст от/до, правило подсчёта: по году рождения или на дату старта, дисциплина или все) привязывается к соревнованию через `competition_age_groups`; если группы выбраны, допуск определяется ими, а `min_age/max_age` рассчитываются как общий диапазон. Пол хранится в `users.sex`. `competition_applications` уникальна по соревнованию и спортсмену и запоминает группу заявки (`age_group_id`). `competition_judges` хранит должности. `competition_results` уникальна по спортсмену/соревнованию и месту/соревнованию.

`rank_applications` относится либо к спортсмену и его результату, либо к судье. Решение с приказом создаёт `sports_ranks` или `judge_categories`; история присвоений сохраняется. `evsk_rules` задаёт только предварительные условия подсветки с источником.

`rating_rules` хранит баллы за места, `ratings` — пересчитываемые суммы с расшифровкой по дисциплине/сезону. `team_members` — вручную выбранный состав сезона. `notifications` одновременно является кабинетным уведомлением и почтовой очередью. `audit_logs` хранит действия, `deadlines` — сроки отчётности. Всего 26 таблиц, внешние ключи, уникальные и CHECK-ограничения, миграция `0001`.

## Авторизация

Все маршруты, кроме регистрации, входа, health и OpenAPI, требуют `Authorization: Bearer <JWT>`. Активный кабинет передаётся `X-Active-Role: admin|athlete|coach|judge`. Если заголовка нет, используется первая доступная роль. Это выбор только из существующих ролей аккаунта.

## Основные маршруты

| Метод и путь `/api` | Назначение / права |
| --- | --- |
| POST `/auth/register`, `/auth/login` | Регистрация с согласием, JWT |
| GET `/auth/me` | Пользователь, роли и идентификаторы профилей |
| GET `/metadata` | Справочники шести дисциплин, типов, организаций; `rating_levels` — уровень для рейтинга по статусу и типу |
| GET `/dashboard`, `/deadlines` | Данные в пределах активного кабинета |
| GET `/athletes`, `/athletes/{id}` | Реестр / доступный профиль; unlinked тренер получает ограниченные поля |
| PUT `/athletes/{id}` | Собственный профиль спортсмена / федерация |
| PUT `/athletes/{id}/suspension` | Отстранение, федерация |
| GET `/coaches`, `/judges` (`?archived=true` — архив, только федерация), GET `/coaches/{id}`, `/judges/{id}` | Карточки; контакты, email и дата рождения видны федерации и владельцу |
| POST `/coaches`, `/judges`; PUT `/{coaches,judges}/{id}` | Создание федерацией (учётная запись по email, для нового — временный пароль) / правка федерацией или владельцем |
| POST `/{coaches,judges}/{id}/archive`, `/restore` | Архивация с причиной и восстановление |
| POST/PUT `/organizations[/{id}]` | Федерация |
| GET/POST `/links`; PATCH `/links/{id}` | Связь с тренером и её история; активация только спортсменом |
| GET/POST `/competitions`; GET/PUT/DELETE `/competitions/{id}` | Календарь; изменение и удаление только черновика федерацией |
| GET/POST `/age-groups`; PUT/DELETE `/age-groups/{id}` | Справочник возрастных групп; изменение запрещено, если группа уже в объявленном соревновании, удаление — если используется |
| GET `/competitions/{id}/eligibility?athlete_id=` | Подходит ли спортсмен по группам: возраст, пол, найденные группы, причина отказа |
| PATCH `/competitions/{id}/state` | draft → open ↔ closed; федерация |
| POST `/competitions/{id}/applications` | Спортсмен за себя / тренер по активной связи и дисциплине |
| PATCH `/applications/{id}` | Федерация: pending → approved/rejected |
| POST `/competitions/{id}/judges` | Федерация; проверка действующей категории |
| POST `/competitions/{id}/results` | Федерация: closed → published, только полный протокол; создаётся редакция 1 |
| PUT `/competitions/{id}/results` | Федерация: исправление опубликованного протокола с основанием, новая редакция |
| GET `/competitions/{id}/protocol-versions` | История редакций: автор, основание, изменения, затронутые разряды |
| GET `/results`, `/assignments` | История выступлений / назначения судьи |
| GET/POST `/rank-applications`; PATCH `/rank-applications/{id}` | Подача / решение федерации с приказом и сроком |
| GET `/ranks` | Доступные разряды и категории |
| GET `/ratings`, `/rating-rules`; PUT `/rating-rules/{level}` | Рейтинг и настройки; изменение только федерацией |
| GET/PUT `/team` | Состав / ручное сохранение федерацией |
| GET `/reports/population` | Федерация: разрезы численности за 2+ года; организация по истории переходов |
| GET `/exports/protocol/{id}.{fmt}?version=N` | Опубликованный протокол; по умолчанию последняя редакция |
| GET `/exports/athlete/{id}.{fmt}` | Отчёт доступного спортсмена |
| GET `/exports/population.{fmt}`, `/exports/team.{fmt}` | Федерация; team с `order=true` — проект приказа |
| GET `/notifications`; PATCH `/notifications/{id}/read` | Только уведомления владельца |
| GET `/audit`, `/users`; PUT `/users/{id}/roles` | Федерация |
| POST `/competition-types`, `/deadlines`; PATCH `/deadlines/{id}` | Справочники и сроки федерации |
| GET/POST `/evsk-rules`; DELETE `/evsk-rules/{id}`; GET `/evsk-candidates` | Настройка предварительных подсказок |
| GET `/athletes/{id}/path` | Личный путь: разряды, цели по `evsk_rules`, следующий шаг; спортсмен, его тренер, федерация |
| GET `/public/glossary` | Справочник понятий, лестница разрядов, баллы рейтинга и условия ЕВСК; без авторизации |

`fmt` = pdf/docx/xlsx. Расшифровка полей и схемы запросов доступны в Swagger `/docs` и `/openapi.json`. Ошибки: 401 — сессия, 403 — права активного кабинета, 404 — запись не найдена, 409 — конфликт уникальности/статуса, 422 — некорректные данные или нарушенное бизнес-условие.

## Решения MVP

Сезон — календарный год даты начала соревнования. Возраст для участия — на дату начала; для рейтинга — на текущую дату; для годового отчёта — на 31 декабря. Разряд «минимальный» сравнивается по упорядоченному справочнику. Места ниже третьего не начисляют баллов, но отображаются в протоколе и рейтинге. При равных рейтинговых баллах сортировка стабильна по ID; регламент отбора сборной остаётся ручным.

Места в протоколе считаются по правилу «1, 1, 3»: место равно 1 плюс число позиций выше. Команда (`competition_results.team_name`) — одна позиция, у её участников общие место и баллы, рейтинговые баллы получает каждый участник. Каждая публикация и исправление сохраняют снимок протокола в `protocol_versions` (номер, автор, основание, строки с ФИО и организацией на момент редакции). Исправление меняет строки `competition_results` на месте, не пересоздавая их: на них ссылаются разряды и заявки на разряд. Состав участников при исправлении не меняется. После исправления пересчитывается рейтинг сезона, участники и их тренеры получают уведомление. Разряды по изменённым результатам не отзываются автоматически: история редакций показывает предупреждение для федерации. Апелляции (Д5) не реализованы.
