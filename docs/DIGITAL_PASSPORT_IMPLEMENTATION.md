# Профили спортсменов, результаты и личные справки

Актуальное поведение изменено по уточнённому требованию пользователя: профиль доступен другим пользователям платформы **только после входа**. Старый публичный паспорт без авторизации отключён.

## Профиль спортсмена

Нажатие на имя спортсмена в реестре, рейтинге, результатах соревнования, истории выступлений, составе команды или списке подопечных открывает `/athletes/{id}/profile`. Это профиль для просмотра, отдельный от личной формы редактирования.

В «Моём профиле» блок **«Результаты»** отвечает за видимость профиля другим пользователям. Сам спортсмен выбирает, показывать ли историю выступлений и статистику, рейтинг, разряды, дисциплины, организацию, муниципалитет, этап подготовки, годы занятий, сборную и прохождение РУСАДА. ФИО и публичный FSP ID остаются основными идентификаторами профиля.

Настройки применяются на сервере: скрытые разделы отсутствуют в ответе `/api/athlete-profiles/{id}`, а не только скрываются CSS. Годы занятий передаются только при включённых дисциплинах и соответствующем переключателе. Контакты, дата рождения, точный возраст, сведения представителя, согласия, ссылки на сертификаты, причины отстранения и справки не входят в профиль посетителя ни при каких настройках.

Видимость профиля не меняет рабочие права федерации и тренера в защищённых реестрах и не удаляет официальные результаты соревнований.

## Справки об участии

В личном разделе **«Результаты»** у каждого опубликованного выступления есть «Скачать PDF» и «Открыть справку». Справка доступна самому спортсмену в роли спортсмена, федерации и действующему тренеру по дисциплине соревнования. Посещение чужого профиля не даёт доступа к его документам. После приостановки связи тренер теряет доступ.

Справка не зависит от видимости профиля, возраста или бывшей публичной публикации: она является личным документом. На ней есть номер `FSP-CERT-{result_id}-V{version}`, сведения конкретного выступления, дата, редакция, SHA-256 и QR.

QR в заново скачанных PDF ведёт на **публичную** страницу `/check-certificate/{token}`. Там без входа показаны только номер справки, соревнование, редакция, дата публикации и статус: подтверждена, редакция заменена либо недействительна. ФИО, FSP ID, организация, команда, место, баллы, контакты и PDF не выдаются. Для недействительной записи название соревнования и дата также скрыты. Неверная ссылка показывает «Справка не найдена».

В личной карточке справки есть кнопка «Публичная проверка». Сама карточка `/certificates/{result_id}?version=N` и PDF остаются защищёнными: права владельца, действующего тренера по дисциплине или федерации проверяются на сервере. Токен публичной проверки этих прав не даёт.

Ссылка подписана HMAC-SHA256 с отдельным доменом `certificate-check-v1`, привязана к снимку протокола и записи результата. Подобрать ссылку по номеру нельзя; смена JWT_SECRET делает ранее выпущенные ссылки недействительными. Миграция не требуется. Публичная проверка не зависит от настроек видимости профиля. Это подтверждение существования записи, не личности предъявителя и не электронной подписи PDF.

Ранее скачанные PDF сохраняют прежний закрытый адрес QR; их нужно скачать повторно.

После исправления протокола актуальная справка содержит новые сведения. Старая редакция остаётся доступной уполномоченному пользователю с отметкой о замене. Справка сформирована автоматически и не является официальным документом; QR не является электронной подписью файла.

## Закрытие старого публичного доступа

Все старые пути `/api/public/passports/*` и `/api/public/protocols/*`, включая JSON, PDF, QR и проверки, возвращают 404 независимо от наличия прежнего токена. Страницы `/p/*` и `/verify/*` не раскрывают данные. Старые настройки публикации `/api/my/passport*` выведены из использования. Ранее скачанные получателями копии файлов технически не могут быть удалены удалённо.

Миграция `0009` добавляет настройки видимости и сбрасывает старые `enabled`/`slug`. Результаты, снимки протоколов, документы и история в БД не удаляются. Downgrade не реактивирует старые ссылки. Таблицы старого паспорта сохранены для совместимости и истории; наружу данные из них не выдаются.

## API

| Метод и путь | Назначение |
| --- | --- |
| GET `/api/my/profile-visibility` | Собственные настройки спортсмена |
| PUT `/api/my/profile-visibility` | Изменение только своих настроек |
| GET `/api/athlete-profiles/{id}` | Профиль для посетителя после входа |
| GET `/api/results/{id}/certificate?version=N` | Личная справка с проверкой прав |
| GET `/api/results/{id}/certificate.pdf?version=N` | PDF с теми же проверками |
| GET `/api/public/certificates/{token}` | Минимальная проверка без входа и персональных данных |

API профилей и документов возвращает `Cache-Control: no-store`. Адрес в QR строится из доверенного `PUBLIC_BASE_URL`, не из заголовка Host.

## Запуск

```powershell
docker compose up --build --force-recreate -d backend frontend
```

Backend применит миграции до `0010`. Том PostgreSQL удалять не нужно. Для QR на другом устройстве `PUBLIC_BASE_URL` должен содержать доступный этому устройству адрес стенда.

## Проверки

Проверены вход перед просмотром, настройки владельца и серверное скрытие разделов, отсутствие личных документов в профиле посетителя, закрытие всех старых публичных URL, получение справки без публикации профиля, запрет для посторонних и судьи, доступ действующего тренера по нужной дисциплине и его отзыв, редакции справок, неопубликованные результаты, доверенный адрес QR и миграции `0008`/`0009`.

API-тесты выполняются на изолированной SQLite в памяти с внешними ключами; PostgreSQL SQL миграций дополнительно компилируется offline. Исполнение новой миграции на пользовательском PostgreSQL из чата не выполнялось.
